## 1. Reply to an enquiry on WhatsApp with a ready-made message

**Type:** Story

**Context:** Staff reply to enquiries by WhatsApp from their laptop, typing the dates, party size and extras by hand each time. The owner wanted one button that opens WhatsApp with the message already written, and wording the owner can change.

**Description:** Added a **Reply on WhatsApp** card to every enquiry (Conversation tab): the guest's number (editable), the message in **English or Italiano**, filled from the enquiry (guest name, property, party, dates, nights, add-ons/transfers), and **Open in WhatsApp**, which opens the WhatsApp signed in on that computer with the message ready. Nothing is sent by the system; staff press Send in WhatsApp, and the message is noted in the enquiry thread. The wording is edited in **Settings → Messages → WhatsApp reply** with details like `{{first_name}}`, `{{dates}}`, `{{party}}`; a line whose details are missing is left out.

**How to test:**
**Before you start:** an enquiry with a phone number, dates, guests and a transfer ticked.
1. Open the enquiry → Conversation tab. Expected: the **Reply on WhatsApp** card shows the guest's number and a message with their name, property, guests, dates and nights, plus "You also asked about: …".
2. Switch to **Italiano** → the message changes to Italian (e.g. "4 adulti, 22–24 ott 2026 (2 notti)").
3. Clear the number → the button greys out and asks for a number with country code. Type `0712 345 678` → it becomes usable (Kenyan number turned into 254…).
4. Press **Open in WhatsApp** → WhatsApp (app or web) opens on that chat with the message. Back on the enquiry, the thread shows "Opened on WhatsApp to +…".
5. Settings → Messages → WhatsApp reply: change the English text, add `{{room}}`, save. Reopen the enquiry → the new wording is used.
6. Type `{{frist_name}}` in the wording and save → refused as an unknown detail.

## 2. Settings page redesign — groups, one Save button, no PHP version

**Type:** Story

**Context:** The General settings page was a long column of cards, each with its own Save button, using browser-default radio buttons and showing the PHP version. The owner asked for a clearer layout with one button to apply changes.

**Description:** Settings → General is now groups that open in place (Booking · Guests & email · Money · Messages · Website · Your account); each closed group shows what is set now. **One Save changes button sits at the top right beside the tabs**: greyed out until something changes, then "Save N changes" with Discard and the list of what changed; changed groups show "N changed". It checks everything first and saves nothing if anything is wrong. Radio cards, switches, lock pills and styled dropdowns replace browser controls. Fetch latest rates, Change password and Export holds keep their own buttons. The PHP version is gone; Migrations moved off the tab row (see the Migrations ticket).

**How to test:**
1. Admin → Settings. Expected: tabs General · Pre-Check-in only; Save changes (greyed) at the top right; Booking group open.
2. Change Booking form mode → the button reads "Save 1 change", the Booking group shows "1 changed", Discard appears.
3. Open Guests & email, change the notification email → "Save 2 changes". Press it → both are saved and named in the message.
4. Enter an invalid email and save → "Nothing was saved" with the reason; what you typed is still there.
5. Press Discard after a change → the page goes back to the saved values.
6. Open Your account → Change password, Download CSV and Open migrations each work on their own. No PHP version anywhere.

## 5. TRI-76 — Account locked much longer than the 10 minutes it says

**Type:** Bug

**Context:** Existing ticket TRI-76. Every try made while locked was counted as another failure (restarting the 10 minutes), and the limit was shared by everyone on the same internet address, so the whole office could be locked by one person's typos.

**Description:** Limits are now **5 wrong tries per account** and **20 per internet address** in 10 minutes. Tries made while locked are not counted, a correct sign-in clears that account's mistakes, and the message says the real time left ("try again in 4 minutes"). Applies to admin, staff-code and travel-agent sign-in.

**How to test:**
1. On /admin/login type a wrong password 5 times for one account → "Too many failed attempts. Please try again in N minutes" with N ≤ 10.
2. Keep trying while locked → the minutes count down (they don't restart).
3. From the same office, another person signs in with their own correct password → it works.
4. After the time shown, sign in correctly → works; earlier mistakes no longer count.
